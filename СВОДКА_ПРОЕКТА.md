# Проект «Путь наблюдателя» — сводка для Claude Project

## Что это
Сайт-курс + VK-бот с психологическими упражнениями + CRM для психолога.
Домен: putnabludatel.ru (HTTPS, Let's Encrypt)

## Инфраструктура
- **Сервер**: Timeweb VPS, IP 5.42.103.203, Ubuntu, PostgreSQL
- **Рабочая папка на сервере**: `/root/Observatory` (НЕ `/var/www/observatory` — это старая заброшенная копия, не используется)
- **База данных**: PostgreSQL, имя базы `put_nablyudatelya_db`, пользователь `observatory_user`
- **Веб-сервер**: nginx → gunicorn → Django
- **systemd-сервисы**:
  - `observatory` — основной сайт (Django+gunicorn)
  - `observer_bot` — VK-бот (python vk_bot/main.py)
  - Команды: `systemctl restart observatory`, `systemctl status observer_bot`, `journalctl -u observatory -n 30 --no-pager`
- **Автодеплой**: GitHub Actions, при `git push` в `main` — автоматически `git pull` на сервере + рестарт `observatory` (НЕ рестартит `observer_bot` автоматически — это нужно делать вручную)
- **Репозиторий**: github.com/Aaantooon/Observatory

## Структура Django-проекта
- `config/` — настройки, главный urls.py, settings.py, кастомная admin-панель (config/admin.py, с jazzmin темой)
- `myapp/` — курс, ментальная карта (React Flow), профиль, VK ID авторизация (myapp/vk_id_auth.py)
- `bot_api/` — модели и API для бота: User, Exercise, Result, ExerciseProgress, Notification, Review, Post
- `crm/` — CRM для психолога (проверка упражнений, карточки клиентов, контент-план)
- `vk_bot/` — отдельный процесс VK-бота (handlers.py, exercises/*, notifications.py, api_client.py)
- `templates/` — HTML. ВАЖНО: `home.html` НЕ наследует base.html, дублирует разметку сама

## Система проверки упражнений (готово)
- Клиент отправляет упражнение → Review (status: pending/in_review/closed)
- Психолог комментирует в CRM (`/crm/review/<id>/`)
- Клиент получает комментарий в боте, может ответить
- Диалог хранится в Review.comments (JSON-список)
- Фоновая проверка новых комментариев — в vk_bot/notifications.py, цикл раз в 60 сек

## CRM (готово, /crm/)
- `/crm/` — список активных проверок
- `/crm/review/<id>/` — диалог по конкретной проверке
- `/crm/clients/` — все клиенты
- `/crm/clients/<id>/` — карточка клиента (упражнения, проверки, прогресс курса)
- `/crm/posts/` — контент-план постов (VK/Telegram/сайт, статусы)
- Доступ: @staff_member_required (нужен is_staff=True у пользователя)


## Известные грабли / паттерны ошибок в этом проекте
1. **Расхождение реальной структуры БД и Django-моделей** — таблицы создавались под старые версии моделей, часто не хватает колонок с дефолтами (is_active, created_at, updated_at) — чинится через `ALTER TABLE ... SET DEFAULT`
2. **`.env` содержит опечатки** — лишние пробелы/кавычки после `=`, разные имена переменных для одного смысла (VK_TOKEN vs VK_GROUP_TOKEN)
3. **DRF router bugs** — методы `@action` иногда вставляются не в тот класс ViewSet (проверять `grep -n "^class "` при ошибках)
4. **URL-адреса в api_client.py не совпадают с bot_api/urls.py** — регулярно нужно сверять
5. **Дублирование кода при правках через nano на сервере** — сервер и git расходятся, чинить через `git checkout -- <file>` перед `git pull`
6. **`/var/www/observatory` — НЕ ТРОГАТЬ**, это старая копия, не связанная с продакшеном

## Как обычно чиню баг (алгоритм)
1. `journalctl -u observatory -n 30 --no-pager` или `journalctl -u observer_bot -n 30 --no-pager`
2. Найти traceback, определить файл и строку
3. Править ЛОКАЛЬНО в VS Code (не на сервере!)
4. `git add . && git commit -m "..." && git push`
5. На сервере: `cd /root/Observatory && git pull && systemctl restart observatory` (и/или `observer_bot`)
6. Если ошибка БД — проверить `python manage.py showmigrations bot_api`, при расхождении — правки через `sudo -u postgres psql -d put_nablyudatelya_db`
