# Тесты VK-бота и сервера

Три файла, три уровня:
- `test_exercises.py` — логика упражнений (`vk_bot/exercises/*`)
- `test_handlers.py` — маршрутизация сообщений (`vk_bot/handlers.py`)
- `test_bot_api_integration.py` — сам сервер (`bot_api/`): настоящие Django-модели,
  настоящие миграции, настоящие DRF-эндпоинты — только база временная
  (SQLite в памяти вместо боевого PostgreSQL). Это единственный файл, который
  реально проверяет сервер, а не то, что бот ПРАВИЛЬНО его вызывает.

Первые два подменяют VK и Django API заглушками из `conftest.py` (без сети
и без сервера); третий поднимает настоящий Django на время теста.

## Как запустить

Из корня репозитория (`D:\observatory`), в том же `venv`, где уже стоит
`Django`/`djangorestframework` (они и так нужны для самого сайта):

```
pip install pytest vk_api
python -m pytest tests/ -v
```

Одна команда прогоняет все 3 файла (35 тестов).

## Что проверяется

`test_exercises.py`:
- редизайн клавиатуры упражнений — 2 кнопки («➡️ Продолжить» / «💾 Сохранить и начать заново»)
- «Продолжить» и «Начать заново» на экране возобновления прогресса
- защита от бага с подстрокой (реальный ответ, случайно содержащий слово
  «заново» или «продолжить», не должен приниматься за команду)
- «Сохранить и выйти» — прогресс сохраняется (не как результат), сессия
  закрывается, повторный вход предлагает продолжить
- валидация неверного ввода (текст без числа/оценки, оценка вне 1-10) —
  не роняет прогресс, не добавляет мусорный пункт
- «Мои роли» — переход между разделами без ограничения на минимум ролей;
  полный флоу с разбором ролей (в т.ч. неверный формат ответа на анализ)
- «Дневник» — нет литерального `None` при сохранении неполного прогресса;
  полный флоу из 6 шагов до конца
- «Осознанный выбор» — полный флоу по всем 5 шагам (включая экраны на
  отдельной `finish_keyboard()`, не тронутой редизайном) до конца
- «Список счастья» — экран 20/20 использует ту же клавиатуру, что и весь сбор
- «Стоп-техника» — счётчик попыток
- «Поиск стресса» — возобновление с середины (фазы analysis/question) не теряет
  и не дублирует данные, результат сохраняется под правильным типом упражнения,
  неопознанный текст на экране анализа не ломает сессию

`test_handlers.py`:
- блокировка меню при активном Review со статусом `in_review` — любое
  сообщение (кроме слов главного меню) перехватывается в комментарий
  наблюдателю вместо того, куда целился пользователь (задокументированная,
  не исправленная особенность — тест закрепляет её текущее поведение)
- обычная маршрутизация: новый пользователь → меню → список упражнений → старт

`test_bot_api_integration.py`:
- API без токена отклоняется (регрессия публичной утечки данных, закрытой 30.08.2026)
- пользователь создаётся/находится по `vk_id` без дублей
- прогресс упражнения — полный цикл сохранить/получить/удалить
- результат — `Exercise` создаётся по строковому `exercise_type`, без дублей
  при повторном сохранении того же типа; отдельно задокументировано (не баг,
  а особенность сервера), что числовой `exercise_type` сервер тоже примет
  без ошибки — защита от этого только на стороне бота (не передавать число)
- результаты фильтруются по `vk_id`
- полный цикл проверки психологом: отправка → комментарий психолога →
  статус `in_review` → очередь комментариев для бота → ответ клиента →
  завершение → статус `closed`
- уведомления: логика «пора ли слать» (`due`) — с задержкой и без,
  однократное уведомление не появляется в `due` повторно после отправки

Стоит перезапускать весь набор после любых правок в `vk_bot/exercises/`,
`vk_bot/keyboards.py`, `vk_bot/handlers.py` — и `test_bot_api_integration.py`
отдельно после любых правок в `bot_api/` (models.py, views.py, serializers.py,
миграции) — перед деплоем на сервер.
